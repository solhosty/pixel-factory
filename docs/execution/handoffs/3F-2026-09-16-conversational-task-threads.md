# Packet 3F — conversational task threads

## Delivered

3F makes each task a single coworker-owned conversation while preserving persisted task, rich-input, plan, decision, recovery, demo, and delivery contracts. The generic project-level decision surface is removed. Decisions, plans, context, Team agreements, requests, and work lifecycle are presented in the task thread.

Tasks start from an occupied desk with an explicit objective and scope. Context editing cannot change assignment or scope. Any context change supersedes an approved plan; a new plan must be explicitly approved before launch. The board is an index only and routes to the same thread.

## Evidence

See [acceptance summary](../../evidence/3F/acceptance-summary.md). The final isolated browser walkthrough included a real local Codex clarification, exact thread routing from desk attention, inbox, and board, persisted ordered task context after reload, and a resolved reply delivered to the same live session. The acceptance run was manually stopped afterward and released its isolated lease.

## Next action

Later packets remain opt-in. Preserve one-thread routing, explicit scope and approval gates, and the separation between implementation acceptance and user visual approval.
