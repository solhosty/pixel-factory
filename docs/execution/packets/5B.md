# 5B — Multi-session employees and bounded collaboration

Prerequisite: 5A.

## Work

- [ ] Expose multiple concurrent sessions under one employee, each with purpose, context, workspace, transcript, and state.
- [ ] Make conversation/terminal selectors target the same selected session. Aggregate active and blocked states accurately.
- [ ] Add explicit review/help requests to another employee or helper session; retain original task ownership and source-linked results.
- [ ] Enforce helper-count, delegation-depth, and retry limits through the shared scheduler. Review uses a stable code snapshot.
- [ ] Combine results, integrate code, verify, and produce one assignment demo. Stop employee stops every owned session; stop session is scoped.

## Acceptance

One employee runs two isolated sessions; one waits for approval while another progresses. Another employee supplies bounded help. Inspect each session in both views, hit a delegation limit, stop/resume, and integrate the result. No false employee sleep while work remains active, duplicate workers, silent shared writes, or infinite delegation.

## Boundary and handoff

No automatic manager recommendations. Cheaper implementation is appropriate for selectors, badges, and bounded request flows with the 5A scheduler fixed; ownership changes merit review. Leave a multi-session fixture and full interaction walkthrough.
