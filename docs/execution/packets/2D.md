# 2D — Shutdown, ownership, automatic recovery

Prerequisite: 2C.

## Work

- [ ] Implement persisted stop reasons, ownership reconciliation, continuation records, and workspace fingerprints.
- [ ] On office closure, suspend owned work and preview processes; detect final client disconnection with a documented grace period. Refresh or a second tab must not create duplicate dispatch or premature shutdown.
- [ ] Reapply 2C capacity admission after ownership reconciliation; reopening must not over-reserve capacity or double-count surviving workers.
- [ ] Automatically resume closure-suspended eligible work on reopening. Manual stops/pauses, pending approval, permission blocks, and recovery conflicts remain blocked.
- [ ] Support stop session, stop employee, pause project, and office-wide controls with sequential session history.
- [ ] Reconcile abrupt service/machine interruption without assuming a missing heartbeat proves a worker is dead. Do not signal unrelated processes based on a reused PID.

## Acceptance

Exercise refresh, last-tab close, two tabs, graceful service stop, forced service interruption, and reopening. No duplicate workers or lost edits/messages; manually stopped work stays stopped. A changed workspace produces reviewable recovery state. Use deterministic fault fixtures and one bounded real Codex recovery run. Record actual process shutdown evidence, not only UI badges.

## Boundary and handoff

Local/sequential only; no remote lifecycle. Recovery deserves focused capable review before completion. Cheaper execution can implement individual documented transitions and fault fixtures. Leave exact reproduction commands and ownership invariants.
