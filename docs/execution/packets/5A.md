# 5A — Parallel scheduler and workspace isolation

Prerequisite: 4B.

## Work

- [ ] Schedule by active sessions/processes using the CPU/memory admission policy from 2C, with configurable account/environment/project capacity ceilings and a durable queue.
- [ ] Give concurrent writers isolated per-repository workspaces or exclusive ownership; preserve base revisions and task affinity on retry.
- [ ] Detect overlapping folder sets and maintain integration order and partial per-repo results.
- [ ] Extend shutdown/recovery and pause controls to all workers without duplicate dispatch.
- [ ] Show working location, queued reason, and account sharing in the office.

## Acceptance

Two employees work independently without same-checkout writes. Exercise capacity queueing, overlapping repositories, conflict resolution, cancellation during dispatch, crash/reopen, and partial integration. Verify combined code after integration. Prove actual ownership/process counts, not just badges. Run bounded real concurrent tasks plus deterministic race/fault fixtures.

## Boundary and handoff

No helper delegation or Coder. Scheduler and isolation require focused capable review. Cheaper models can implement individual queue transitions and fixtures from the approved ownership contract. Leave invariants, race reproductions, and integration commands.
