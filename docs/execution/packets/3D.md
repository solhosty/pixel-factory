# 3D — Reproducible demos and verification

Prerequisite: 3C.

## Work

- [x] Save per-repository code fingerprints/revisions and check commands/results.
- [x] Implement demo recipes with setup, fixtures, dependencies, start/readiness commands, owned ports/processes, and cleanup.
- [x] Present a sit-down demo with runnable UI review, relevant non-UI proof, checks, and known gaps.
- [x] Support request changes and acceptance; changed code makes previous evidence visibly stale.
- [x] Keep demo acceptance separate from delivery and project completion.

## Acceptance

Launch the reviewed multi-repo fixture from its recipe, verify readiness and checks, review it, request a change, and show old evidence becoming stale. Re-run and accept fresh evidence. Exercise setup failure and occupied-port handling without killing unrelated processes. A completion message or screenshot alone cannot mark unverified work verified.

## Boundary and handoff

Recording is optional; reliable live/screenshot evidence is required. No PR publication here. Cheaper implementation is suitable once lifecycle and evidence contracts exist; inspect the actual meeting and preview. Leave a runnable fixture recipe for 3E.
