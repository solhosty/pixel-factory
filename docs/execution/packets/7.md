# 7 — Office manager and expanded release

Prerequisite: 5B. Coder is not required.

## Work

- [ ] Derive optional suggestions from recorded outcomes: repeated setup failure, missing checks, recurring task boundaries, or useful skill proposals.
- [ ] Link every suggestion to its evidence and show a concrete proposed change with accept/dismiss controls.
- [ ] Keep rejected suggestions from recurring unchanged; exclude credentials and unrelated project context.
- [ ] Apply only authorized suggestions through existing work/review flows; do not silently install skills or change permissions.
- [ ] Expand approved asset kits and update contributor setup, support matrix, and release rehearsal. Material new visual treatments return for pictures/interactive approval.

## Acceptance

A repeatable fixture produces an evidence-backed suggestion. The user can inspect, dismiss, or approve it; dismissal produces no mutation. Approval results in the proposed reviewable change. Another user can follow the documented setup and complete a task. Preserve visual quality and truthful supported-capability labels.

## Boundary and handoff

No speculative self-optimizing agent framework. Cheaper implementation is suitable for deterministic suggestion rules and approved interface components; review any new autonomous policy. Leave fixture inputs, suggestion rationale, and release limitations.
