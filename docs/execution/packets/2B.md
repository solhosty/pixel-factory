# 2B — Objective planning, guidance, and messages

Prerequisite: 2A.

## Work

- [ ] Add objective clarification and versioned plan proposals: milestones, tasks, dependencies, acceptance criteria, assignments. Planning may run; proposed implementation cannot dispatch before approval.
- [ ] Store approval of a specific plan version; material revisions invalidate the affected gate, not unrelated approved work.
- [ ] Add follow-up message queue with visible pending/delivered/failed states and duplicate-resistant dispatch using the 00 contract.
- [ ] Add scoped project guidance with provenance, correction/retirement, and task selection of relevant records. Keep working notes separate.
- [ ] Wire real requests into the inbox and show which guidance each session received.

## Acceptance

Propose a plan, request clarification/revision, approve it, and run the resulting task. An unapproved or superseded plan cannot launch implementation. Send a follow-up during work and verify delivery to the intended session. Correct guidance and show the next relevant session receives it; unrelated projects do not. Reload preserves pending requests and message state.

## Boundary and handoff

UI-specific design meetings are in 3A; no vector memory system or autonomous task expansion. Suitable for cheaper execution against explicit state transitions. Leave gate/queue tests and guidance selection examples for 2C and 2D.
