# 6 — Optional Coder execution

Prerequisite: 5B; explicit decision to start optional remote work. This packet is a larger integration milestone: use its checklist as separate session handoff boundaries when needed.

## Work

- [ ] Inspect current Coder interfaces and define a remote adapter, lifecycle, capability, and authentication contract; use research-harness only as a verified reference.
- [ ] Add server/account/repository onboarding, environment setup, remote CPU/memory discovery and capacity enforcement using the 2C policy, and live remote coworker status in the 2C list. Account for shared-host limits rather than assuming each workspace owns the whole machine.
- [ ] Treat each added ready Coder environment as an additional pool of remote worker slots, bounded by its CPU/memory and any shared-host ceiling. Let users add/assign remote coworkers to that environment; adding capacity alone must not launch work. Keep persistent staff separate from runnable slot counts.
- [ ] Integrate environment pools into the 2C coworker list and office-wide task board, showing assignment, status, location, active/available slots, and capacity blocks. Remote coworkers do not occupy or consume a workstation in the company Office. Unavailable environments block new dispatch while retaining coworker/task history and unconfirmed running state where applicable.
- [ ] Preserve per-task/per-repo workspaces, credentials in their supported remote locations, transcripts, and demo evidence.
- [ ] Implement disconnect/reconnect reconciliation and acknowledged remote stop. Distinguish stopped task processes from running Coder infrastructure.
- [ ] Run parallel remote tasks and delivery through the same review and approval model as local tasks.

## Acceptance

Real configured Coder environment runs two bounded tasks, returns changes and demos, survives disconnect/reconnect without duplicate workers or lost work, and acknowledges stop. Demonstrate adding a second ready environment exposes its own remote capacity, assigning coworkers to each pool, and independent capacity queueing. Verify shared-host ceilings do not double-count resources. Show both environments’ tasks on the office-wide board and coworkers in the remote list, with no remote characters or consumed workstations in the company Office. Disconnect one environment: its records remain visible and the other pool stays usable. Local-only setup still requires no Coder. Unreachable stop remains unconfirmed. Record remote prerequisites and support versions; local mocks alone cannot complete this packet.

## Boundary and handoff

No infrastructure purchase/provisioning or external publication without applicable authorization. Remote transport/auth/lifecycle need capable review. After contract approval, cheaper sessions can implement one checklist item at a time and leave incremental handoffs. Missing remote access is an explicit blocker, not remote readiness.
