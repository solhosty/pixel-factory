# 3B — Employee roles, skills, character roster, and office growth

Prerequisite: 3A.

## Work

- [x] Add the fixed position taxonomy: Designer, Frontend Engineer, Backend Engineer, Fullstack Engineer, Security Engineer, Project Manager, and Marketing. Positions may repeat and remain independent of local/remote execution location.
- [x] Give each position a curated default skill bundle. Let customers enable built-in skills and add or author reusable employee skills. Keep skills separate from permissions, tools, accounts, environment access, and task folder scope.
- [x] Resolve position defaults, employee skills, project guidance, and task instructions at launch. Persist the exact resolved skill configuration on the session so later employee edits do not rewrite history.
- [x] Replace free-form appearance recipes with predefined complete character identities. Allow only employee naming for initial character setup and enforce that one active employee owns a character identity at a time.
- [x] Ship enough distinct, complete character families for the initial roster. Every family needs consistent standing, four-direction six-frame walking, seated, sleeping, and portrait states and must pass the `/studio` and populated-office review gates.
- [x] Replace project-owned and doorway-connected rooms with one company-wide Office. Remove the adjoining Quiet workroom. Projects remain available through employee desks, conversations, filters, and the office-wide board.
- [x] Compose and review a polished Studio layout with six to eight persistent workstations. Local employees, assigned or available, occupy desks; remote employees consume no desk and never appear physically. Empty desks remain intentional scene elements.
- [x] Define the capacity boundary for a full Studio. Do not append procedural rooms or automatically rearrange/shrink the office. Larger capacity requires a separately composed, versioned, and visually approved layout.

## Acceptance

Create employees with repeated and different positions, customize their skill sets, reload, and prove a launched session retains the exact resolved skill snapshot after the employee profile changes. Reject duplicate active ownership of one character identity. Inspect every character state in `/studio`, then populate the Office without duplicate identities. Fill and free local desks, move an employee between local and remote, and confirm remote staff remain operationally visible without appearing or consuming a desk. Confirm projects change work context without creating rooms. Walk the entire six-to-eight-desk Studio at supported sizes and reduced motion; verify collision, depth, seating, density, and visual quality against the approved warm-studio reference. No Quiet workroom or doorway transition remains in the product flow.

## Boundary and handoff

This packet changes the employee domain and office composition, not execution capacity: saved staff and desk counts do not raise the 2C worker ceiling. Do not install customer skills, grant capabilities, or change permissions implicitly. Character generation follows the approved asset workflow and requires full-state integration rather than isolated portraits or recolors. The Studio and every future larger layout require concrete visual review. Leave a resolved-skill fixture, character ownership tests, and a populated-office walkthrough for 3C.
