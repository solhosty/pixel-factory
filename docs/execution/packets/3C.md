# 3C — Employee assignment and rich task composition

Prerequisite: 3B.

## Work

- [ ] Make an employee selectable from both the Office and coworker sidebar. Both entry points open the same persisted employee record and expose one consistent **Assign new task** action when the employee is available.
- [ ] Use one canonical task composer everywhere task creation appears. Entering through an employee preselects that employee while allowing the user to change or clear the assignment before saving.
- [ ] Support a Codex-like task brief with text, pasted content, images, files, selected project folders, tagged project/employee/task context, and task-specific instructions. Make attached and tagged context visible and removable before submission.
- [ ] Persist task drafts and every referenced input before dispatch. Preserve stable attachment/context identities, provenance, ordering, and availability state; do not depend on transient browser-only objects or silently omit an unavailable input.
- [ ] Resolve task inputs into the launched session explicitly, alongside the skill snapshot established in 3B. Treat attachments and tagged context as task inputs, not implicit permissions or expanded filesystem scope.
- [ ] Keep planning, saved assignment, and execution authorization distinct. Creating or assigning a task must not bypass plan approval, launch a worker implicitly, or weaken the existing explicit-dispatch and folder-scope contracts.
- [ ] Preserve the one-active-assignment rule. A busy employee opens their current assignment and history; the UI must not offer or accept another active assignment until the employee is released.
- [ ] Keep direct task creation, Office assignment, coworker-list assignment, office-wide board state, and session navigation on the same task, assignment, employee, and session records.

## Acceptance

From the populated Studio, click an available local employee, open **Assign new task**, attach an image and a non-image file, select multiple project folders, add tagged project/employee/task context, and save without dispatch. Reload and confirm the draft and input order remain intact. Open the same draft from the coworker sidebar and office-wide board, change the selected employee, and verify every view agrees. Approve and explicitly launch the task; prove the intended session receives every available input and no unselected folder or implicit permission. Exercise missing/inaccessible attachment handling without silent omission. While the employee is active, reject a second assignment; after completion, assign a new task while retaining identity and assignment history. Verify keyboard and reduced-motion access to the same flow.

## Boundary and handoff

This packet improves task definition and assignment entry points; it does not add parallel assignments, new execution capacity, or automatic dispatch. Reuse the established attachment/context model across every entry point rather than creating Office-specific payloads. Rich inputs must cross local service and harness boundaries through explicit supported mechanisms and fail visibly when unsupported. Leave a persisted rich-task fixture and an employee-originated assignment walkthrough for 3D.
