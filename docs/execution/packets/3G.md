# 3G — Task workspace and multi-task ownership

Prerequisite: 3F. This is a product-model correction that comes before 4A. It supersedes the single-active-assignment rule without bringing parallel execution, provider expansion, or employee-to-employee delegation forward.

## Intent

Make the task—not the employee profile—the primary working surface. A task opens a focused, styled rendering of its own Codex conversation and session state. Employees can own multiple active tasks, each with a separate persisted session and conversation. The task board is the operational index; Inbox is the cross-task list of work needing a user response; Skills is a global management surface.

## Work

- [x] Replace the employee sidebar's assignment/status card with a task-first entry: selecting an occupied desk, coworker, board row, or inbox item opens the relevant task workspace, not an employee profile panel. Place employee actions, including Stop employee and room-presence controls, in the employee header rather than a body disclosure.
- [x] Build a task workspace that presents the selected task's conversation, plan/decision/request states, attachments, and session state in the approved pixel-office style. Provide the existing raw terminal/history treatment as an alternate **Session** view within that task workspace. The user must be able to switch between the styled conversation and the actual native terminal for that same selected session; neither view launches another execution.
- [x] Redesign **Tasks** as a task board with To do, In progress, Done, and Cancelled columns. Keep ownership, concise state, blocking reason, recency, and task/session identity visible. Each card opens exactly its task workspace.
- [x] Redesign **Inbox** as cross-task actionable work: clarifications, approvals, decisions, recovery conflicts, and delivery review. Each item opens its exact task message or decision.
- [x] Provide distinct app tabs for **Mailbox** and **Profile & skills**. Mailbox is the employee-specific message/history surface; Profile & skills is the employee-specific identity and skill surface. Remove their disclosures, project disclosure, and inactive-terminal filler from the employee panel.
- [x] Change assignment/session ownership so an employee can have multiple active tasks and each task retains its own assignment history, session, context, workspace scope, and terminal lease. Preserve task completion, cancellation, reopening, and reassignment history.
- [x] Keep execution sequential until 5A: starting work on a second task must show a durable capacity/queue state rather than run concurrent writers. Do not share a terminal, process, checkout ownership, or unscoped context across tasks.
- [x] Preserve 3F's one-thread task routing, 3C's explicit rich-input/scope contract, 2B plan gate, 2D recovery, 3A decision immutability, and 3E delivery lifecycle.

## Acceptance

Create two active tasks for one employee with different selected folders and independent task conversations. Start one task, then show the other as queued or otherwise not executing under the sequential capacity rule. From **Tasks**, open each card and verify its own styled conversation and its own actual terminal/session selector; sending context, replying to a request, or viewing output never crosses task boundaries. Confirm an Inbox clarification and a decision route to their exact task messages. Complete, cancel, and reopen tasks and verify their board lanes and employee assignment history. Reload with both tasks present and prove task/session identity, scope, context, and queue state persist. Verify desktop and narrow browser layouts plus keyboard and reduced-motion paths.

## Boundary and handoff

No second provider or account profile (4A), automatic usage fallback (4B), concurrent execution/workspace isolation (5A), or helper delegation/multi-session collaboration (5B). “Multiple active tasks” means multiple durable task records and session ownership; it does not authorize simultaneous execution. Leave a persisted two-task fixture, served-browser walkthrough, and an ownership/queue contract for 5A.
