# 4B — Automatic fallback and usage availability

Prerequisite: 4A.

## Work

- [ ] Classify quota, authentication, permissions, capacity, unknown availability, and general failures separately.
- [ ] Automatically hand off to an eligible enabled connection on confirmed quota failure, retaining workspace and employee identity.
- [ ] Build continuation context from task/decisions/messages/code/evidence; label new native sessions honestly.
- [ ] Sleep only when all eligible options for unfinished work are confirmed exhausted. Track supported reset information without invented precision.
- [ ] Resume when availability returns while the office is open; preserve manual stops, pending gates, deduplication, and bounded retry behavior.

## Acceptance

Controlled quota fixtures trigger fallback, complete pool exhaustion triggers sleep, restored availability triggers a single resume. Authentication or unknown availability never appears as quota sleep. A real cross-provider continuation preserves a disposable edit and receives the intended context; simulated quota injection is explicitly labeled. No actual account exhaustion is required for testing.

## Boundary and handoff

No parallel workers. Suitable for cheaper execution against explicit classifier and state-machine fixtures; escalate uncertain provider semantics rather than guessing. Leave failure samples with sensitive data removed and exact tests.
