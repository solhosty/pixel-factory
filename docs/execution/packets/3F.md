# 3F — Conversational task threads and decisions

Prerequisite: 3E implementation contracts. This is a user-experience follow-on to 3C, not a replacement for its persisted task, input, and approval contracts.

## Intent

Make a task feel like a focused conversation with its assigned coworker. The task board is an index of work; it is not a second authoring model. Project guidance and decision versions remain durable records, but are created and resolved in context rather than exposed as standalone internal forms.

## Work

- [x] Replace the generic task-composer-first flow with a single task thread. Starting work with a coworker begins with a plain-language objective; the coworker asks only for information that is genuinely missing.
- [x] Keep text, pasted context, files, images, folders, and tagged records available from a compact **Add context** affordance. Show every attached item as a removable, named chip in the thread before it is sent.
- [x] Render the task lifecycle in the same thread: intake, clarification, proposed plan, explicit plan approval, work updates, requests for a decision, demo, and delivery outcome. Each state must say plainly what is waiting on whom.
- [x] Turn a material decision into one actionable in-thread request: recommendation, options, trade-offs, affected work, and clear **Approve** or **Request changes** actions. Do not expose a generic meeting/version creation form in the normal project view.
- [x] Move project-wide reusable instruction into **Team agreements**. A user can save an in-thread instruction there deliberately; ordinary task messages do not become implicit guidance. Preserve scope and provenance internally.
- [x] Make every task entry point converge on its one thread: coworker, occupied desk, attention indicator, inbox, and task board. An attention indicator opens the relevant coworker and exact request, never just a generic panel.
- [x] Redesign the task board as a readable work index with owner, concise status, last meaningful update, and blocking reason. Opening a row returns to the same task thread.
- [x] Remove or disable every decorative/control-looking element that lacks a real action. Keyboard and reduced-motion paths must reach the same thread, attachments, decisions, and inbox state.

## Acceptance

Create a task from an occupied desk with a one-sentence objective. Continue the conversation through exactly one necessary clarification, attach an image and a text file through **Add context**, save/reload, and confirm the same ordered context is present. Review and approve a proposed plan in that thread, then explicitly launch it. Cause a real clarification and a versioned decision request: the desk attention marker and inbox entry both open the assigned coworker at the exact message; replying or approving returns work to the correct state. Save one explicit Team agreement and prove it is scoped/provenanced, while ordinary conversation is not promoted to guidance. Open the same task from the board and prove it returns to the same thread/session. Verify all of this in a served browser at supported desktop and narrow widths, with keyboard and reduced-motion operation. Preserve the 3C rich-input guarantees, 2B plan gate, 3A immutable decision approval, 2D recovery, and 3E delivery semantics.

## Boundary and handoff

Do not add parallel sessions, helper delegation, or employee-to-employee collaboration; those remain 5A/5B. Do not weaken explicit plan approval, delivery authorization, input provenance, scope, or durable history. Keep the technical records behind the conversational surface so existing migration and execution contracts remain valid. Leave a persisted conversational-task fixture and a served-browser walkthrough for later release review.
