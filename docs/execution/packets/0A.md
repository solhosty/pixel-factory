# 0A — Pictures, interactive approval, and reusable visual kit

Prerequisite: 00. **Asset creation is currently deferred. Obtain explicit user authorization to start this visual phase before generating pictures or assets.** This packet records future work only until then.

## Work

- [ ] Create a small set of distinct still-image treatments within the confirmed top-down RPG direction. Show the same office, employee, conversation panel, and inbox in each so the user can compare actual design choices. Include a populated scene, not only an empty room.
- [ ] Present pictures for feedback. Revise until the user explicitly approves a specific direction/version. Record the approved image paths and feedback in `docs/design/APPROVALS.md`.
- [ ] Build an interactive prototype of the approved direction: movement, furniture navigation, employee interaction, conversation/terminal switching, inbox, option review, and sitting down for a demo. Use clearly simulated execution data.
- [ ] Let the user try the prototype and request revisions. Record separate approval of the interaction and motion; picture approval alone does not approve how it feels.
- [ ] Establish E03: palette, perspective, pixel scale, character proportions, source formats, renderer, animation timing, supported display scales, target hardware, supported window sizes, reduced motion, and measured frame/input budgets. Record these in `docs/design/VISUAL_SPEC.md`.
- [ ] Deliver reusable environment pieces, character layers, animation clips, interface components, and a gallery covering idle/work/approval/sleep/error states. Record asset identifiers, source files, exports, pivots, collision footprints, and provenance in `docs/design/ASSET_MANIFEST.md`.
- [ ] Assemble the populated six-to-eight-workstation Studio using the same kit and exercise multiple distinct character identities. Preserve readable long-form conversation and terminal typography.

## Acceptance

Still-image direction and interactive prototype each have explicit user approval tied to artifact versions. The prototype and walkthrough are available; the gallery demonstrates consistent rendering and transitions, including long content, error states, keyboard use, and smaller windows. Measured performance meets the recorded target. The fully populated Studio reuses the kit without sacrificing composition quality. No placeholder scene is presented as final artwork; raster concepts alone are not animation-ready assets.

## Boundary and handoff

No real employee execution or production persistence. Leave approved screenshots, runnable prototype commands, reusable source assets/components, gallery URL, visual specification, and approval records. A later implementation session must preserve these references. Material visual changes reopen review; implementing approved components does not.

Art direction and motion judgment warrant a capable design session and user review. Cheaper models can build gallery cases, export tooling, and approved component variants using exact visual references. Do not expect a vague “make it stunning” prompt to substitute for approved artifacts.
